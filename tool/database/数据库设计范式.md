# 数据库设计范式

## 数据库三范式

数据库的三范式（1NF、2NF、3NF）是关系型数据库设计中用于减少数据冗余和依赖的规范。以下是每个范式的定义和例子：

### 第一范式（1NF）：列的原子性

一个关系型数据库表的每一个字段（列）都是不可分割的基本数据项，即每个字段都是原子性的。

**例子**：

假设有一个“员工”表，包含“姓名”和“联系方式”两个字段。如果“联系方式”字段中存储了多个电话号码，并且用逗号分隔，这就违反了1NF，因为“联系方式”字段不是原子性的。

**解决方案**：

将“员工”表拆分为两个表：“员工基本信息”和“员工联系方式”。“员工基本信息”表包含“员工ID”和“姓名”，“员工联系方式”表包含“员工ID”和“电话号码”。

### 第二范式（2NF）：消除部分依赖

在1NF的基础上，非主键字段必须完全依赖于主键，而不是依赖于主键的一部分。

**例子**：

假设有一个“订单”表，包含“订单ID”、“客户ID”、“客户名称”和“订单日期”。如果“客户名称”依赖于“客户ID”而不是整个“订单ID”，这就违反了2NF。

**解决方案**：

将“订单”表拆分为两个表：“订单”和“客户”。“订单”表包含“订单ID”、“客户ID”和“订单日期”，“客户”表包含“客户ID”和“客户名称”。

### 第三范式（3NF）：消除传递依赖

在2NF的基础上，非主键字段不能依赖于其他非主键字段，即没有传递依赖。

**例子**：

继续使用上面的“订单”和“客户”表的例子。假设还有一个“产品”表，包含“产品ID”、“供应商ID”和“供应商名称”。如果“供应商名称”依赖于“供应商ID”，而“供应商ID”是“产品”表的主键的一部分，这就违反了3NF。

**解决方案**：

将“产品”表拆分为两个表：“产品”和“供应商”。“产品”表包含“产品ID”和“供应商ID”，“供应商”表包含“供应商ID”和“供应商名称”。

通过遵循这些范式，数据库设计变得更加规范，减少了数据冗余，提高了数据的一致性和完整性。然而，过度规范化可能会导致查询性能下降，因此在实际应用中需要根据具体情况权衡。
